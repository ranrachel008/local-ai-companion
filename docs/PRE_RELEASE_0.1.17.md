## 新版發布前必須補完的 Agent 驗收

本輪按順序執行，不開新的平行 Qwen 任務。以準備發布的最新 Agent 為測試入口，保留目前模型、宿主、端口及啟動參數。

1. 先讀實際 tools/list 與工具 schema。從已成功搜索的真實返回取得 job／candidate 身份，讓日常 Qwen 聊天依序實際呼叫 scout_research、scout_plan、scout_job；不得猜參數或 ID。若現有工作不能續用，僅建立所需的新工作。
2. 允許取得公開源碼的固定快照、只讀研究和保存計畫。研究要有可追溯文件位置、原命令及依賴／环境證據；三階段保持同一候選、倉庫、精確 commit、來源快照及指紋綁定。缺失資訊如實標 UNKNOWN，不能用一般知識補成成功。
3. 計畫步驟須追溯研究證據；区分依賴、本體安裝及人工前置項。確認適用的本體安裝步驟存在、目標環境一致、固定來源策略清楚。REVIEW_REQUIRED 是正常待審閱狀態，不要求整份計畫全自動。作者或社群真實跑通教程仍可作證據，不因缺少官方同款說明自動排除。
4. 核對工作持久狀態：研究及計畫已保存，但未取得安裝批准、未開始安裝。沿已驗證方式僅重啟 Agent 子進程，再从聊天頁使用原 job 身份查詢；來源、證據、計畫及狀態不得丟失。
5. 在隔離測試工作／副本做必要的負面驗證：無效或跨工作候選綁定、來源指紋不符、上游連線／超時／解析錯誤。均須明確拒絕或停止，不能吞錯報成功。模擬錯誤須標為模擬，不能代替成功路徑的真實聊天證據。
6. 再補一條不帶 owner/repo 的普通需求搜索，確認仍有可追溯候選；它是一般搜索冒煙驗證，不把指定倉庫查證擴大成所有搜索策略都通過。
7. 保存實際聊天工具事件、完整結構化返回、最終回答及工作狀態。截圖若無法保存，如實記錄；既有可靠的聊天證據可沿用。記錄實際耗時，研究／計畫須完成或按現有超時與停止機制明確結束。
8. 只修本輪發現的相關缺陷，驗證受影響路徑；源碼若變動，重新建立對應 Agent 成品並核對 Build ID。回報各項 PASS／FAIL／BLOCKED／UNVERIFIED，通過且無未解重大缺陷後才恢復發布。

本輪不執行 pip、建立候選 Python 環境、安裝系統工具、執行候選倉庫程式、下載模型或授予安裝批准。重大發布阻擋項包括身份錯綁、缺本體安裝、虛構／錯報成功、未授權安裝及持久狀態丟失；誠實的未知資訊與人工審閱項須按其實際影響記錄。

README 應讓普通使用者先選擇：
1. 想用視窗搜尋、研究與審閱安裝：下載 GUI。
2. 想讓現有本地聊天宿主呼叫工具：下載 Agent 並依 QUICKSTART 接入 MCP。

模型不會包含在這兩個包裡。日常使用以 GUI 或既有聊天頁操作為主。

安裝計畫說明應寫明：使用者可交由雲端 AI 協助審閱，或自己審閱後在 GUI 確認；實際批准仍由人類操作，Agent 沒有安裝執行權限。

## 發布前只做交付一致性檢查

1. 從實際正在使用的 MCP 配置定位驗收通過的新 Agent，取得 EXE 路徑、Build ID、來源指紋及雜湊。不要把修復前 agent.1 的舊 Build ID 當作新包證明。
2. 對 GUI 與 Agent 分別核對：待發布 ZIP、包內 EXE／隨附檔案、BUILD_INFO 與源碼指紋相互一致；ZIP 可以正常讀取及解壓。GUI 成品若保持原樣，不需重建。
3. 發布副本的範例配置可供其他使用者替換本機路徑；移除憑據、私人工作紀錄、聊天原文、環境目錄、模型、備份及原始 HTTP／SSE 診斷資料。保留已做脫敏的精簡驗收說明。
4. 把新源碼與文件放入發布 commit，固定 tag；若兩元件源碼不相同，分別保留精確對應的來源快照。
5. 先建立 Draft Release 並標記 Prerelease，附齊所有下載資產。核對 GitHub 上的資產清單、大小及可用雜湊／下載內容與本地一致，再發布。

既有定向測試、真實聊天搜尋及 GUI 人工驗收無需全面重跑。若發布包有新的程式碼或配置變動，只驗證受影響的部分。
